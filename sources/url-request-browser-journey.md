## 视频画面要点

视频以同一张六面板图逐步高亮，展示下面的教学顺序：

1. 输入网址。
2. DNS 域名解析。
3. TCP 三次握手，标有 SYN、SYN-ACK、ACK。
4. TLS 握手，配证书与锁的示意。
5. 发送 HTTP 请求，配 GET、200 OK 和服务器/数据库示意。
6. 页面渲染，配 HTML、DOM 与页面示意。

这些是画面内容的改写归纳；更详细的运行条件及协议例外来自下方补充核验。

## 核验与适用边界

于 2026-10-24 查阅以下一手技术资料：

- [MDN：浏览器如何工作](https://developer.mozilla.org/en-US/docs/Web/Performance/Guides/How_browsers_work)，Navigation、Response、Parsing、Render 小节：用于核对解析、连接、响应和渲染的基本职责。该页的固定 TLS 往返次数表述不作为本笔记结论。
- [MDN：HTTP 缓存](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching)：核对响应复用与需要重新验证的区别。
- [RFC 9114：HTTP/3](https://www.rfc-editor.org/rfc/rfc9114.html)，1、3 节：核对 HTTP/3 使用 QUIC 及连接复用。

核验后的补充：

- 六步适合作为“需要联网、建立新连接、使用 HTTPS over TCP、获取 HTML 文档”的入门模型，不是每次请求都完整经过的固定步骤。
- DNS 缓存、可复用 HTTP 缓存与已有连接是不同机制；复用已有结果可能省去查询、传输或建连。缓存需要重新验证时仍可能联网。
- HTTP/3 使用 QUIC，不能套用独立的 TCP 三次握手流程。
- 视频中的数据库是服务端示例，不代表所有请求都查询数据库。渲染还涉及 CSS、脚本及子资源，不能只理解为 HTML 转成 DOM。
