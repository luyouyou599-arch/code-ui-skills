# 任务依赖与执行顺序检查

先从需求与实际配置提取任务、前置条件及边的含义，用一个明确例子确认“谁必须先于谁”。按 [references/decisions.md](references/decisions.md) 验证图和执行边界。

根据项目现有工具选择实现，优先复用已有依赖排序或构建能力。仅需生成顺序时，不额外搭建并发执行平台。需要执行任务时，区分已就绪、运行中和成功完成；确定失败后下游如何处理，不把拓扑顺序误当执行成功。

完整顺序必须满足所有前置约束并包含全部任务；若存在环或缺失依赖，报告可定位的信息，不静默删边或返回部分列表冒充成功。同一依赖层可能有多个有效顺序，除非业务要求，不把某个唯一顺序作为正确性标准。

项目阐述时，用实际任务和依赖说明为何需要此机制、串行/并行的选择、失败边界及验证依据。未实现并行或恢复就不宣称已有这些能力。
