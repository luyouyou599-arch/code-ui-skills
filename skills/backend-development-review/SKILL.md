# 后端开发与验收入口

在后端开发中主动选择相关检查，不等用户逐项点名。开发任务在设计和实现后各检查一次有关边界；纯评审任务只报告问题及建议，不擅自改变代码。明确要求全项目验收时，先枚举实际入口和关键业务路径，再按风险分批覆盖，记录未覆盖范围。

## 确定检查范围

读取目标项目的规范、需求、实际改动和已有测试，沿“入口 → 身份/授权 → 业务规则 → 数据/外部依赖 → 响应/副作用”定位受影响路径。检查调用方及必要相邻模块，不把单个接口修改扩大成无关全库整改。需求缺失时先查项目材料，仅对影响判断的缺口询问；不能用代码当前行为反推正确需求。

优先识别业务不变量，例如用户只能修改自己的对象、重复请求不能重复扣减、失败不能留下半成品。将这些条件转换成输入、预期结果、实际副作用和可验证证据。

## 按场景调用知识库

下列链接指向本库独立技能。通过用户级链接加载本入口时，先解析自身真实目录，再定位相邻目录；不要相对于当前业务项目拼路径。只读取当前改动匹配的技能和其所需参考，避免一次加载整个库。缺少某个技能时明确缺失，先检查项目已有依据，不伪称已调用。

| 触发条件 | 按需调用 | 重点查找 |
| --- | --- | --- |
| 本次 AI 功能涉及模型结果、检索或工具调用的质量与回归 | [ai-workflow-evaluation-checkpoints](../ai-workflow-evaluation-checkpoints/SKILL.md) | 任务样本、判定标准与调用证据；纯界面样式不加载 |
| 功能目标、角色、业务行为或验收预期不清 | [product-task-checkpoints](../product-task-checkpoints/SKILL.md) | 使用情境、成功结果、允许/拒绝规则与可观察副作用；只补当前缺口 |
| 接口、外部调用、错误处理、多步写入或生成代码验收 | [web-request-checkpoints](../web-request-checkpoints/SKILL.md)，尤其其后端验收参考 | 输入边界、响应与业务结果、超时与重试、事务覆盖和重复副作用 |
| 登录、受保护资源、用户/租户关系、知识检索/记忆隔离或角色变化 | [auth-access-checkpoints](../auth-access-checkpoints/SKILL.md) | 服务端对象授权、跨租户检索/上下文/缓存访问、身份过期和撤权；不以隐藏按钮证明权限安全 |
| SQL/ORM、统计、关联、排序或分页 | [sql-query-checkpoints](../sql-query-checkpoints/SKILL.md) | 漏数、重复计数、空值、稳定排序、结果对象含义 |
| 缓存、消息、异步、库存/名额预留或服务入口/边界 | [architecture-tradeoff-checkpoints](../architecture-tradeoff-checkpoints/SKILL.md) | 数据归属、一致性、重复消费、原子预留与重试、失效和故障传播，按实际机制检查 |
| 初始化步骤、任务前置关系 | [dependency-order-checkpoints](../dependency-order-checkpoints/SKILL.md) | 依赖方向、缺失节点、环、就绪与完成条件 |
| 运行配置、流水线、部署或数据版本兼容 | [release-deployment-checkpoints](../release-deployment-checkpoints/SKILL.md) | 凭据来源、制品、失败门禁、持久化、恢复与兼容 |

这个路由覆盖现有知识库，不能将未涵盖领域视为已通过。文件上传、命令执行、出站 URL、密码处理等特殊入口出现时，读取实际框架和当前一手安全依据，补充与改动相关的验证；资料不足时记录缺口，不能只因表中没有就略过。

## 验证并处理发现

每个问题说明触发条件、实现位置、影响和证据，区分已复现、代码支持但未运行的风险、待核实假设。不把偏好、缺少某种技术或理论上的可能性当作确定漏洞。按越权、数据损坏、错误业务结果、资源影响等实际后果排序。

先复用现有测试与工具，必要时添加能暴露该缺陷的回归用例；关键路径检查正常、边界、失败与相关并发场景。测试断言应依据需求并检查持久化副作用，不只断言状态码。修复时验证用例能捕捉原错误，再确认修复和受影响回归；没有环境时明确未运行的内容。

在开发/修复授权范围内处理问题并重跑相关检查；纯验收按发现交付。使用隔离数据与本地/授权测试环境，不进行生产越权、破坏性故障注入或真实第三方攻击。检查权限不自动授权部署或更改线上数据。

## 交付与项目拆解

说明检查范围、调用的知识点、按严重性排序的问题及代码位置、修复状态、实际运行结果与未覆盖项。没有发现问题时表述为“在本次范围和验证条件下未发现”，不承诺没有漏洞或 bug。项目阐述以已实现的业务不变量、控制位置和测试证据说明核心机制与取舍，不把建议列为成果。
