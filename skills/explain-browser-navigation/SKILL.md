# 解释网页加载流程

根据读者基础与问题深度解释网页导航。用户未提供具体场景时，使用“访问 HTTPS 网页、需要联网、建立新的 TCP 连接并返回 HTML”作为教学前提，并明确这是简化模型。不要把教学前提说成已观察到的实际请求行为。

## 讲解方法

先用一条主线建立整体认识：确定访问目标 → 找到网络地址 → 建立连接和安全通道 → 交换请求与响应 → 处理资源并显示页面。

按用户需要，使用 [references/navigation-guide.md](references/navigation-guide.md) 解释每阶段解决什么问题、产出什么、交给谁。类比后回到真实术语；避免只背缩写或步骤编号。

讲完主线后，补充会改变流程的条件：DNS/HTTP 缓存、已有连接、HTTP/3。不要把这些分支讲成所有请求都依次执行的额外步骤。

用户要面试答案时，先给精简口述版，再附少量追问；用户要入门解释时，优先讲职责及前后关系。用户提供现有答案时，指出具体错误和成立条件，再给修订版。

## 检查输出

- DNS 是地址解析，TCP 是可靠传输连接，TLS 是安全协商，HTTP 是应用层请求与响应；不要互相替代。
- 不把“每次都查 DNS、建 TCP、做 TLS、查数据库”当作通则；不将 HTTP/3 说成基于 TCP。
- 区分获取 HTML、加载子资源、首次显示及可交互；没有测量数据时不给故障结论或固定耗时。
- 若用户问真实网页为何慢，先定位缺少的请求时序或浏览器性能证据，再按证据分析，不能仅凭六步图定位问题。
