# 后端接口改动的验收证据

用于审查具体后端接口改动，包括 AI 生成的代码。先读取需求、改动范围、接口调用方与现有测试，按失败影响选择条目；不因使用 AI 就扩大成全系统审计。

| 使用场景 | 关键决策与易漏项 | 验证方法 |
| --- | --- | --- |
| 参数与计算 | 确定缺失、空值、上下限、非法类型和除零等相关输入的业务语义 | 用需求独立写预期输入/输出，检查响应与实际副作用；不能把生成代码当前结果直接当测试答案 |
| 外部服务失败 | 超时不必然表示对方未执行；确定错误转换、超时预算与是否允许重试 | 在隔离环境模拟超时、错误响应和重复请求，确认没有重复写入或错误成功反馈；没有副作用的功能不套资金场景 |
| 多步写入或并发修改 | 明确业务不变量、事务覆盖的数据库边界和并发冲突策略；数据库回滚不自动撤销外部调用 | 按实际业务在中间步骤注入失败，检查数据状态；必要时使用两个并发请求验证。未实际执行不称并发安全 |
| 集合接口变慢 | 检查循环查库、无界加载与资源占用，不把缺少缓存直接判为缺陷 | 随集合规模增长测查询次数、实际查询记录和延迟；针对代表数据验证分页或批量访问。是否加缓存取决于一致性与证据 |
| 验收用例看似齐全 | 确认断言覆盖业务结果及失败后状态，必要的依赖边界不能全部被 mock 掩盖 | 对照需求遗漏表选择单元/集成/回归；在隔离环境用已知错误或被移除的关键逻辑确认相关测试会失败，不要求每次改动新增所有测试类型 |

涉及身份/对象访问时检查服务端授权及跨用户、租户场景；涉及 SQL 时检查参数绑定而非拼接输入，动态列名/排序需允许列表或框架受控映射。涉及凭据时检查代码、配置和日志暴露范围。需要发布时再核对监控、告警和恢复路径。沿用目标项目现有组件，不强制引入新设施。

项目拆解记录实际业务不变量、失败分支、实现边界及测试结果。测试数量、覆盖率或本地可运行都不能单独证明业务正确。
