# 配置默认值、排序与预览的检查

| 场景 | 关键决定与易漏项 | 验证方法 |
| --- | --- | --- |
| 根据上下文推荐默认值 | 明确推荐的依据、可编辑范围与何时重算；已有保存值或用户已修改值不应被晚到推荐无意覆盖。推荐不是已确认或已保存 | 新建/编辑、上下文切换、推荐晚到、用户先修改再收到推荐；确认值的来源和业务范围，允许保留或撤销适用的推荐 |
| 本地实时预览 | 区分输入草稿、有效预览和已保存配置；无效输入保留可修正状态，不把最后有效预览误标成新值生效 | 暂时无效值、连续修改、取消与重置；检查预览、提交负载与刷新后的配置一致性。若只是本地草稿，不能显示已保存 |
| 远程预览或自动保存 | 先选择显式保存还是自动保存；预览接口应明确是否产生副作用。异步结果按资源和草稿版本对应，旧响应不能覆盖新编辑 | 快速编辑、断网、响应乱序、保存失败和离开页面；保留未保存输入并提供恢复，收到成功后也不能把其后的新改动清成已保存 |
| 拖拽排序 | 用稳定对象标识表达顺序，明确跨组/分页/隐藏项的边界。提供无需拖拽的点击/触屏方式并验证键盘操作，单有键盘路径并不足以覆盖全部拖拽替代需求 | 中止拖拽、点击上移/下移、首尾边界、排序后编辑正确对象；检查焦点和保存后的顺序，避免用旧索引修改错项 |
| 排序持久化 | 决定本地即时呈现、何时提交及失败后恢复；不能只移动画面而未保存，也不能把旧失败的回滚覆盖后续已完成的排序 | 连续两次排序、先后响应相反、保存失败与重新读取；按请求版本关联结果，不重复追加或丢失对象 |
| 同一配置被并发编辑 | 界面保留草稿并解释冲突，服务端按资源版本或条件写入处理；默认后写覆盖需有明确业务依据 | 两个客户端读取同版本后先后保存，确认过期写入被识别，用户能比较、重新加载或重新应用改动；不能用前端单请求锁代替服务端冲突控制 |

按业务选择最小必要复杂度：单人本地原型不强制增加版本 API，成熟组件库已有的排序/表单能力优先复用。没有代码和接口时，交付这些状态与契约约定，不能声称已保存或已测。

2026-10-24 核对：[WCAG 2.5.7 拖拽移动](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html) 将单指针无需拖拽替代与键盘可用性分别评估；[RFC 9110 §13.1.1](https://www.rfc-editor.org/rfc/rfc9110.html#name-if-match)、[MDN If-Match](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/If-Match) 说明条件写入与避免丢失更新的机制，具体业务还需服务端原子检查。
