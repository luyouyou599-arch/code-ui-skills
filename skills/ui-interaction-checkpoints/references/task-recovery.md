# 任务可发现性与恢复检查

先确认当前页面要完成的任务、数据含义、用户权限和服务端结果，再选择相关行。以下为网络媒体配文的条件化提炼及工程补充，尚未在目标项目实测。

| 使用场景 | 关键决策与易漏项 | 验证方法 |
| --- | --- | --- |
| 列表或搜索为空 | 区分首次无内容、筛选无匹配与加载失败，写清原因；只给当前权限下有用的动作。无匹配可清筛选，不应暗示原数据被删除 | 分别构造空库、无匹配、无权限与请求失败；清筛选保留正确上下文，恢复后展示真实数据 |
| 需要比较多个方案 | 对齐单位、价格口径和关键差异；可选推荐需有依据且能改。收起低频项时保留可发现入口；主动同意或后果不明时不代选 | 常用与特殊需求各走一遍；不同价格组成、长名称、无推荐历史；确认默认值未悄悄增加费用 |
| 用户在局部任务卡住 | 就近帮助使用用户词汇与可执行步骤，必要时提供目标入口；导航回来保留草稿。重复求助先检查是否该修入口，不默认加全屏教程 | 用户常用同义词能找到帮助；链接到当前可操作位置，按现有权限工作，关闭后焦点和输入仍在 |
| 提交中的局部错误 | 说明具体字段/对象和可行改法，错误持续到被处理；保留正确输入。不能把未知失败猜成图片大小等具体原因；技术码可辅助排障，不替代解释 | 单项及多项错误、网络中断、修正重试；错误关联与焦点合理，无整表清空；结果不确定时先查结果再决定重发 |
| 高频或批量操作 | 依频率、对象数量选择快捷键、手势或批量；保留普通入口。批量需明确所选范围，不能把“本页全选”默认为“所有结果”；删除后果按真实风险决定确认/撤销 | 键盘与触屏入口；跨页、筛选变化、部分失败与撤权，显示成功/失败对象并保留可恢复选择；前端多选不替代服务端逐对象授权 |
| 跨页填写或重复选择 | 显示必要摘要、可辨认选项和可编辑历史，减少强迫记忆；历史默认值不是用户对本次交易的同意 | 返回编辑、历史已失效、无历史、清除历史；摘要和实际提交一致，不把别人的历史带入当前账号 |
| 日期区间或重要提交 | 展示开始/结束语义和业务计数，如入住/退房与晚数；确定无效值可提前限制，不确定意图不要静默改值 | 同日、跨月/年、夏令时、禁用日期以及服务端规则变化；按业务时区验证晚数，不机械用毫秒除以24小时；提交前摘要与请求一致 |

操作层级还需保留当前决策所需金额、时效和对象等事实；促销或次要操作不能挤掉主任务。点击次数只是线索，配合任务是否成功、错误及恢复成本判断。
