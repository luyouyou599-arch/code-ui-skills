# 发布与部署检查

先读取实际构建命令、流水线、运行配置和发布目标，区分代码提交、测试通过、制品生成、部署完成与用户可用。按现有技术栈检查；没有发布系统的任务不因本技能而新增平台。

- 修改自动化流水线、流量切换或回退：读取 [references/release.md](references/release.md)。
- 涉及容器镜像、端口、数据持久化或编排健康检查：读取 [references/containers.md](references/containers.md)。只检查当前项目实际采用的部分。

每个检查点对应具体配置、失败影响与验证方法；优先修复会导致错误版本上线、失败检查被绕过、数据丢失或无法恢复的实际问题。发布策略根据用户容忍中断程度、成本与可观测性选择，不将蓝绿、金丝雀或 Kubernetes 作为默认要求。

有实际发布授权时，按项目流程执行，并在目标环境验证版本、健康状态与关键用户路径；仅审阅配置时不能声称已上线或已回滚。流水线绿灯与进程运行都不能单独证明业务可用。

阐述项目时沿“提交 → 制品 → 目标环境 → 放量 → 观测/恢复”追踪真实证据，说明哪些环节自动化、为何选择该策略、承担什么成本，以及回退能恢复哪些内容。未演练的恢复步骤明确标为待验证。

运行时安全公告、镜像或托管包修补任务，按需读取 [references/runtime-updates.md](references/runtime-updates.md)，确认供应商修复证据与实际运行实例，不以代码仓库版本代替部署结果。
