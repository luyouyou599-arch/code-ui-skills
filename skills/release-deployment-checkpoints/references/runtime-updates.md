# 运行时修补的实际覆盖

适用于当前任务涉及运行时安全公告、依赖镜像升级或托管环境修补；不因普通后端修改而自动进行全网扫描。

- 先将官方公告映射到真实服务路径、运行时/模块、包来源及受支持分支。发行版回移补丁用供应商证据判断，版本号较旧不能单独判定未修复。
- 确认被检查的是实际服务进程及其制品：开发机 CLI、FPM/应用工作进程、容器、后台任务可能不同；安装新包而旧工作进程未更换，仍不能算部署完成。按本次范围检查实例与旧副本。
- 区分业务代码修复、运行时修补与临时降暴露措施；临时措施的限制、撤销方式和补丁计划需明确。不要从媒体文章直接复制放宽资源限制等配置。
- 按已有发布授权处理构建、兼容性检查与部署；回退制品若含旧漏洞要重新评估，不能只求恢复流量而永久退回已知风险版本。

验收证据：公告/供应商包修复记录、制品身份、实际运行版本或包构建信息、实例替换结果、健康与关键路径回归。托管场景向供应商核实适用范围与修复状态。证据缺失写待确认，不能以仓库升级或 CLI 输出替代生产部署结果；未经授权不探测第三方目标。

案例：网络媒体 [运行时安全更新](https://www.xiaohongshu.com/explore/6ad99606000000003102692f)，2026-10-24 完整配文已读。核对 [PHP 安全公告](https://www.php.net/archive/2026.php#2026-10-21-5) 的补丁与供应商回移说明；这里的通用检查为整理者推导，不写死 PHP 版本。未执行升级或漏洞验证。
