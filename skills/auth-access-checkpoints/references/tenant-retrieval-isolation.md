# 多租户检索、上下文与缓存隔离

仅在目标功能涉及多租户知识库、检索增强生成（RAG）、会话记忆或租户相关缓存时读取。输入是实际身份/租户映射、读写入口、检索条件、上下文存储及缓存实现；没有材料就列待查点，不宣称发现漏洞。

| 使用场景 | 关键决策及易漏项 | 验证证据 |
| --- | --- | --- |
| 请求选择租户或知识库 | 服务端将调用身份与允许操作的租户绑定，再选择存储/检索范围。请求参数、模型生成的工具参数、namespace 名称本身不证明权限 | A 身份伪造 B 租户、集合或文档 ID；拒绝且无读取/写入副作用；缺少租户不能落到无范围查询 |
| 文档入库、切片与检索 | 先选项目可强制执行的隔离边界，所有相关读写入口使用；租户隔离之外，仍可能有租户内不同角色的文档权限。不要只在生成答案后让模型隐藏敏感内容 | 用可区分的测试文档追踪检索结果、送入模型的片段和引用；A 不能获得 B 的片段，同租户低权限用户也不能获得受限片段；授权变更后复查 |
| 复用历史、摘要、记忆或工作线程 | 每次从已授权的会话范围组装上下文；不能把同一全局列表、上个请求残留或可猜的线程 ID 当安全边界。清理时点按保留需求确定，不要求合法会话每次清空 | 交错执行 A/B 请求、重用工作进程、互换会话 ID，检查实际上下文组装结果；允许的同会话连续对话仍能工作 |
| 应用回答/语义缓存 | 命中结果前仍须满足当前访问范围；键与元数据覆盖会影响可见结果的租户/用户/权限条件。全局公共数据可明确共享，不能把所有缓存统一视为私有或统一共享 | 先用 A 预热，再让 B 提相同和相似问题；检查缓存命中路径也不能返回 A 私有内容。权限撤销、资料删除后验证失效或重新授权路径 |
| 声称隔离已经通过 | 设计说明、只检查最终回答或几条成功断言均不够；受影响链路需验证拒绝和正常情况 | 记录身份、测试数据、入口、期望/实际结果；按风险纳入现有回归或 CI。涉及数据库策略时使用应用实际角色和连接复用方式；未执行的项目保持未验证 |

实现选择按项目存储和风险决定，不强制每租户独立实例、所有表都含同名列、或每次查询同时使用 namespace 与冗余过滤。隔离名称只有在服务端正确路由和访问约束下才有意义。具体供应商的 namespace/collection 语义不能互换。

应用层“答案缓存/语义缓存”与推理服务的 KV/前缀计算缓存作用不同。对后者先核对所用产品的缓存隔离、会话和数据保留文档；不据名称断言都能由应用加 tenant_id，也不因一个命中就断言必然泄露。模型是否共享也不能单独证明系统安全；这里只检查实际数据访问链，不声称覆盖训练数据或供应商全部风险。

以上表格是网络媒体观点的条件化应用与整理者测试推导，未运行真实系统测试。来源：[多租户 Agent 数据隔离](https://www.xiaohongshu.com/explore/6adb0039000000002403eda8)，正文及 9 张图读取于 2026-10-24。

一手核验（2026-10-24）：[OWASP 多租户安全](https://cheatsheetseries.owasp.org/cheatsheets/Multi_Tenant_Security_Cheat_Sheet.html) 支持服务端可信租户上下文、按结果权限范围区分缓存和实际访问路径验证；[OWASP RAG 安全](https://cheatsheetseries.owasp.org/cheatsheets/RAG_Security_Cheat_Sheet.html) 支持片段继承权限及检索时授权；[Pinecone 多租户实现](https://docs.pinecone.io/guides/index-data/implement-multitenancy) 是 serverless 每租户 namespace 的产品实例，不能泛化到所有向量库。
