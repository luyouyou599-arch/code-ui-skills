# 适配、路由与执行的验收样本

只用于当前 AI 功能相关的改动。先取一个真实失败例，确定期望与禁止结果，检查实际输入、上下文、路由或调用结果，再决定改哪一层；不能因一个回答错误就直接引入训练、检索或多代理。

## 任务适配与检索

- 若关键资料缺失、过期或无访问权，先核对资料进入上下文的过程；若资料正确但行为、术语或格式仍不稳定，再比较提示/示例和适用的任务调优。检索与调优可组合，选择依据失败类型、维护成本和证据，不依据“某方法已过时”的概括。
- 比较改动时固定独立验收样本，训练/调参用过的例子不能单独证明改进。除目标任务外保留与改动相邻的常见能力样本，记录错误是否转移；这里不要求实际发起训练或付费调用。
- RAG 同时检查：证据是否被取到，回答各项主张是否受当前证据支持，是否遗漏关键限定条件。引用存在不代表主张受支持；与上下文一致也不代表上下文真实、及时或完整。
- 最小有意义样本可包含：正确且充分资料、检索漏项、相互冲突/过期资料、问题超出资料范围、答案遗漏条件。缺证据时应怎样澄清、拒答或转交由产品规则确定；拒答本身也需检查是否阻止了本来可回答的任务，不用“全拒答”换取表面零错。

## 意图到处理路径

明确各意图边界及执行方：能由确定代码完成的路径、需要模型的路径、无法判断的恢复路径，不自动要求专用分类模型。用已标注的真实任务比较路由正确性与端到端结果，不能只测标签格式。

按需求补未知意图、歧义/多意图、信息不足、用户中途改意图，以及不同错误代价的样本；多意图先定义产品预期，不强行转成单标签。若使用 confidence/分数，检查其具体含义，在本任务标注样本上检查高分错例、分数区间表现、误执行与转交成本。高 confidence 不代替业务授权，阈值与错误代价有关，不沿用厂商例子的固定数字。增加意图或换模型后重跑相关回归。

## 参数到实际执行

对应用自定义工具，分别判断工具选择、参数语义、执行及结果回传；模型给出调用请求不代表操作已完成。若用托管工具，先确认实际执行方与可见结果契约。

当多个工具能力相近或工具清单变化时，检查实际发送给模型的名称、描述与参数约束是否能区分用途、返回内容及限制。用“查状态 / 改状态”等相邻任务、无需工具即可完成的任务及缺必要信息的任务比较选择结果；记录预期工具、实际选择或未调用、参数和最终结果。误选时先定位是描述歧义、可用工具不对还是上游路由错误；只改描述后也需回归相邻任务，不把 schema 合法当成选对工具。此组样本是根据媒体线索与官方工具定义文档补充的工程推导，未实跑。

可选样本：同义表达是否映射到正确单位/地点/业务对象；必要参数缺失是否澄清；合法类型但错误对象/过期数据是否被执行层拒绝；未调用、执行失败或部分成功后，最终回答是否仍声称完成。参数 schema 校验与服务端对象授权、业务约束是不同检查，不能让模型传入的身份字段代替可信身份。

有副作用时按真实接口的幂等、超时和重试语义验证；调用 ID 用于关联结果，不能自动当业务幂等键。并发或重试测试只在已授权的隔离环境执行。反馈结论与实际持久化/第三方结果对照；不以回答“已成功”作为断言。
