# Git 改动与协作检查

先读取项目 Git 规范，检查当前分支、工作区、暂存差异及相关历史，再按 [references/decisions.md](references/decisions.md) 选择当前操作所需的检查。不要顺序执行整套命令。

每项决策说明要解决的具体问题、会影响的文件或历史，以及验证依据。提交前确认暂存内容与当前任务一致；同步前确认目标远端与分支、是否分叉及项目整合方式。遇到冲突，先理解两边意图，不能为消除冲突而覆盖他人改动。

撤销时先区分未提交内容、仅本地提交和已被协作方依赖的历史。按项目规范选择保留历史的反向提交或其他明确策略；不能把 reset、restore 和 revert 当同义操作。涉及丢弃内容或改写共享历史时确认具体范围和已有授权。

项目阐述时，根据真实分支图、提交、PR 和验证记录说明改动如何拆分、评审、整合和回退；不要将使用 Git 包装成产品核心技术，也不因存在 tag 就声称发布已验证。

完成后检查预期差异与历史变化；运行与实际代码变更相称的检查。命令执行成功不等于功能正确。没有实际仓库材料时仅给候选方案，不断言存在冲突或流程缺陷。
