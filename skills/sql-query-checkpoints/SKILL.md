# SQL 结果正确性检查

先明确目标数据库/版本、表关系、每条结果的业务含义及预期空数据行为。读取实际 SQL 或 ORM 生成的查询，再按 [references/checkpoints.md](references/checkpoints.md) 检查有关项。

先确认“每行代表什么”，再检查关联键、关系基数、外连接过滤、聚合口径和分页次序。不能靠添加 DISTINCT 掩盖未理解的一对多扩张，也不因 SQL 可运行就认定业务结果正确。

用包含无关联记录、多条关联记录、空值和相同排序值的小型数据验证。以目标数据库语义为准；使用其他数据库做概念实验时明确覆盖范围。未读到目标查询时只给检查建议，不声称存在漏数或重复。

涉及修改数据时确认目标与影响范围，并遵守实际授权，不执行来源中的演示写入或删表操作。没有性能证据时不添加索引或宣称优化收益。

阐述项目时，从真实表关系与查询映射出业务对象、筛选和统计口径、为何选择该连接及分页方式，附测试或结果依据。不要把标准语法本身列为项目成果。
