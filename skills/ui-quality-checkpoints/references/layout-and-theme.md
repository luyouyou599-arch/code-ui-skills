# 布局关系、主题与层级

## 内容与容器怎样分工

先确定容器方向、间距、内边距、对齐及是否允许换行，再明确子项尺寸来自内容、剩余空间还是固定边界。设计工具中的 Hug/Fill/Fixed 是理解关系的起点，不与某条 CSS 声明一一等价。

- 标题/操作同行：内容区域可缩放，按钮按内容或约定最小尺寸；检查长标题、翻译及窄屏换行。
- 输入与操作同行：输入占剩余宽度；Flex 子项自动最小宽度可能阻止收缩，按内容决定是否设置 `min-width:0`、换行或保留滚动。不能用隐藏溢出掩盖丢失的关键文字。
- 标签与卡片：按实际信息关系使用 Flex/Grid 和断点；固定头像不意味着固定整张卡片高度。区分阅读顺序和视觉顺序。

验证真实长内容、无空格长串、200% 文字放大及窄视口；检查重叠、截断、按钮被挤出和意外双向滚动。没有实现代码时只交付布局约束，不宣称响应式已通过。

## 浅深色与浮层关系

主题使用语义变量表达表面、正文、次要文字、边界、强调和状态；按主题共同配置，而非把所有颜色简单反相。用户手动选择、系统偏好与保存策略应有明确优先级。`prefers-color-scheme` 表示系统偏好，不能覆盖明确的用户选择。

深色下可用表面亮度、边界与适当阴影共同表达层级，但不能假定某种亮度必然代表前后；原生控件、图表、图标、焦点和状态也要核对。纯黑/纯白不是绝对禁用，最终按实际对比、平台与品牌判断。

阴影变量应反映普通容器、菜单与模态等实际层级，z-index 和交互遮挡仍需单独验证；没有“偏移必须大于模糊一半”或“最多三层”的通用规定。列表可用分隔和留白，不必每行加阴影。

验证两个主题中的关键状态、透明叠层与背景变化后的文字对比，主题切换后仍可见的焦点与当前选择；相关改动还要核对首次加载的主题和用户设置保存情况。
