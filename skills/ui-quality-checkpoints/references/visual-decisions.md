# 视觉一致性与交付检查

| 使用场景 | 关键决策与易漏项 | 验证方法 |
| --- | --- | --- |
| AI 初稿或组件样式漂移 | 先复用项目 spacing/type/color/radius 变量；区分组内、组间和版块间距。相同语义保持一致，允许光学对齐与特殊布局例外 | 对照实际样式与代表页面；用真实内容检查对齐、拥挤和分组，避免仅统计数字种类 |
| 嵌套圆角容器 | 对等距、同心、同形圆弧，可将内半径约为外半径减内缩距离作为起点；边框、非等距内边距、胶囊形和尺寸约束需另看 | 检查实际尺寸与渲染后的四角、边框间隙和裁切，不能只套等式 |
| 文字层级不清 | 先定标题、正文、辅助与交互角色，再选择字号、字重、行高和宽度；沿用系统尺度，不强制只用四个字号 | 长标题、正文段落、数字、中文与英文混排；窄屏与文字放大后检查截断、重叠和阅读顺序 |
| 颜色抢眼或内容难读 | 按文本、表面、强调与状态分配语义颜色。饱和度不是可读性判定；正文色取决于实际背景，深色模式也需核对 | 测量合成后前景/背景对比；WCAG 2.2 AA 普通文字至少 4.5:1，大号文字至少 3:1，注意标准例外与大号定义 |
| 视觉稿准备交付 | 确认相关组件的焦点、禁用、错误、加载等真实状态，不把静态美化当作功能验收 | 实际键盘路径与焦点可见性；相关视口、缩放、长文案和状态截图；不使用颜色作为唯一信息线索 |

4/8/16/24、14/16/24/32 可以是某个页面的候选尺度，不是跨项目强制值；#1A1A1A 与低饱和配色属于条件化选择。单一例子不能证明某风格普遍更高级。

依据（2026-10-24 核对）：[WCAG 2.2 快速参考](https://www.w3.org/WAI/WCAG22/quickref/) 的 1.4.1、1.4.4、1.4.10、2.1.1、2.4.7 等；[文字对比解释](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。这里只选择与当前改动相关的检查，不代表完整合规审计。
